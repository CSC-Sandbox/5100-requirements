# Contributing to CSC 5100

This repository supports coursework, collaboration, and code review in CSC 5100. Follow the instructions for each assignment or lab; this guide describes the shared GitHub workflow.

## Workflow

1. Read the relevant assignment or lab instructions and any linked issue.
2. Create a descriptive branch for your work; do not commit directly to `main`.
3. Make focused commits with meaningful messages.
4. Open a pull request (PR) against `main`, linking the relevant issue and describing your changes.
5. Include evidence that the work runs, such as test results, commands, screenshots, or API responses, as appropriate.
6. Respond to review comments and push revisions to the **same branch and PR**.
7. Request another review when ready. The instructor reviews and controls approval and merging.

## Issues and discussions

Use GitHub Issues to ask assignment-related questions, report problems, or track work. Keep implementation discussions and revision notes in the associated issue or PR whenever possible. Be respectful, constructive, and specific.

## Pull request checklist

- [ ] I followed the relevant assignment/lab requirements.
- [ ] My PR links the related issue (when applicable).
- [ ] I explained what changed and how I verified it.
- [ ] I did not commit secrets, credentials, or unnecessary generated files.
- [ ] I addressed existing review feedback (if applicable).

## Review and grading

A PR is a submission for review, **not** automatic approval or a guarantee of credit. Follow the course's published deadlines and grading instructions. Keep your PR open while addressing requested changes unless the instructor directs otherwise.

## Repository changes

Propose improvements to shared course materials through an issue or PR. Do not modify another student's work without coordination. Only the instructor merges changes into the protected main branch.
